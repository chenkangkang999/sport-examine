# 医生及管理端前端

本目录是 Vue 3 与 Element Plus 实现的医生工作台和管理员界面。医生端保留手册中的左侧查询、右侧预约表格，以及检查结果和总检结论录入结构；管理员在同一应用中维护基础资料与医院排班。

## 代码入口

| 文件或目录 | 职责 |
| --- | --- |
| `src/main.js` | 挂载 Vue、路由和 Element Plus 中文组件 |
| `src/App.vue` | 系统页头、登录人员信息、退出及管理员导航 |
| `src/router.js` | 登录守卫、管理员路由及过期会话跳转 |
| `src/api.js` | `/tijiancms` 请求、独立 staff 会话、CSRF 与错误提示 |
| `src/style.css` | 工作台公共布局、查询栏、表格和报告样式 |
| `src/views/Login.vue` | 医生或管理员登录 |
| `src/views/Orders.vue` | 按手机号、姓名、性别、套餐、日期及状态查询、分页 |
| `src/views/Report.vue` | 检查分项录入、异常展示、结论增删改和归档 |
| `src/views/Catalog.vue` | 医院、套餐、检查项目及医生账号维护 |
| `src/views/Associations.vue` | 医院可预约套餐关联 |
| `src/views/Schedules.vue` | 每院每日名额设置及已占用数量展示 |
| `vite.config.js` | 管理端 8089 端口和后端开发代理 |

## 报告页面的状态流转

`Orders.vue` 查询预约后，通过 `/orders/:id` 打开 `Report.vue`。该页取得检查分项、总检结论、预约状态和 `reportVersion`。

每个分项保存时携带当前版本号，服务器返回保存后的报告与新版本。页面会保留其他分项尚未保存的填写内容。另一个窗口先提交后，本窗口再用旧版本保存会收到 409，提示重新加载最新报告。数值是否异常由后端参考范围计算，描述项由医生标记。

归档前先保存所有已修改分项，填写全部必填结果并至少保存一条总检结论。归档成功后，报告对医生只读，用户端才可查看。前端的角色导航和只读样式用于交互引导，账号权限、医院范围、版本及归档条件都由后端再次校验。

## 本地启动

完整启动方式见[仓库运行说明](../README.md)。仅启动此端时，在本目录执行：

```powershell
npm ci
$env:VITE_API_TARGET = 'http://127.0.0.1:8080'
npm run dev
```

浏览器打开 `http://127.0.0.1:8089/`。如果后端实际使用 18080，将 `VITE_API_TARGET` 改为该端口，再启动 Vite。演示账号和完整业务演示步骤见[答辩演示说明](../docs/DEMO.md)。

```powershell
npm run build
```

构建产物在 `dist/`。正式提供静态文件时，Web 服务器还需代理 `/tijiancms` 和本端使用的 `/tijian` 请求到后端。

## 修改界面时的约定

- 保留医生端查询栏与报告表单的原有蓝灰色布局，避免把页面改成与手册无关的仪表盘。
- 性别筛选的“全部”表示不限定性别，与“男”“女”同时保留。
- 共有的表格和表单布局优先在 `src/style.css` 修改；特定业务字段在对应页面修改。
- 管理端 staff 和用户端 user 分别登录、退出，可在同一浏览器中配合演示。
- 基础资料通过停用保留历史引用，订单和报告展示预约时的快照。
