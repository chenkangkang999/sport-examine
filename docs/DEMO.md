# 课程演示与答辩步骤

## 演示一：本人或家属预约

1. 启动项目，打开用户端，使用演示账号登录；也可以注册虚构新用户。
2. 在家属档案中新建体检人。输入合法格式、生日及性别一致的虚构18位身份证，界面只显示脱敏证件。
3. 发起预约，选择体检人、机构、适用套餐和有余量的日期。
4. 确认页检查姓名、机构、套餐和后端价格，勾选课程练习支付说明后点击“确认支付”，不产生真实扣款。
5. 在我的预约中查看订单；刷新页面仍能读到数据。
6. 在医生尚未录入结果前取消另一条预约，观察日期名额恢复，订单保留为已取消。

## 演示二：医生录入、归档与用户报告

1. 在管理端用所选医院的医生账号登录：医院一 D001，医院二 D002。
2. 使用用户手机号或姓名筛选刚创建的订单，打开报告编辑页。
3. 分项输入检查结果并保存。范围或等值数值由服务器计算异常，文本项目由医生明确标记。
4. 添加总检结论；可演示修改和删除结论。
5. 尝试在有必填项缺失时归档，系统应阻止；补齐后归档。
6. 返回用户端查看已发布报告，包括异常项、总检结论和完整明细。
7. 再次进入管理端，此报告为只读；用户不能取消该订单。

## 演示三：管理、权限与历史记录

1. 管理员登录，维护医院、检查项明细、套餐、机构套餐关联和医生账号。
2. 为某医院批量设置日期名额与开放星期；已占用数量大于目标容量时，调整应被拒绝。
3. 修改套餐名称或价格，既有订单仍显示预约时的价格与名称。
4. 医院二医生不能打开医院一订单，其他用户不能打开本账号订单。
5. 同一浏览器同时登录用户端与管理端，退出一端不会退出另一端。
6. 停止后端后重新启动，之前订单和报告仍然存在。

## 可说明的课程知识点

- HTML/CSS 页面迁移为 Vue 组件、路由与双向绑定；Axios 完成前后端 JSON 交互。
- Spring MVC 处理请求，Service 封装业务，MyBatis 参数化 SQL 操作 MySQL。
- Spring 事务保证名额、订单、报告快照、演示支付的一致性。
- 索引、外键、唯一约束、条件更新与版本校验分别处理重复数据、越权和并发。
- 后端会话、CSRF 校验与密码哈希组成基础身份保护，路由守卫仅改善页面体验。

全部医疗结果和支付均用于虚构课程演示，不连接真实诊疗或交易系统。
