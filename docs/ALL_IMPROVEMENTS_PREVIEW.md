# 全部改进：功能与使用说明

本文说明截至2026年11月15日的功能、界面规则和体验入口，版本更新记录见 [CHANGELOG.md](../CHANGELOG.md)。用户端内容页共用柔和医疗底图，手机与电脑中间应用区域同步，电脑两侧保持原灰色。图片仅作页面底图，卡片、表单、导航和弹窗使用不透明白底；彩色登录页、个人中心顶部、成功页渐变等原有彩色区域保留。个人中心默认一屏菜单、原有菜单顺序及退出登录最后一项继续保留。

## 数据口径

- 首页、订单、报告和消息均按当前账号查询，医生待办强制限定所属医院，统计和机构指南维护仅管理员可用。
- 趋势只读取已归档报告，按体检人、稳定检查明细标识、名称、单位和类型分组；不把不同单位的数据放进同一条折线。
- 参考范围使用每次报告的快照；历史参考范围发生变化时逐次说明，不把当前范围覆盖到所有历史点。
- 站内消息在预约、取消和归档事务中生成，重复提交不产生重复消息；消息已读状态保存在数据库。
- 每日名额与使用率按所选体检日期区间汇总；取消订单不占用名额，归档率在有效预约中计算。
- 本轮仅增加通知和机构指南两张辅助表，不重置既有订单、检查结果、价格或个人资料。

既有数据库升级脚本为 `database/migrations/20261114-experience-features.sql` 和 `database/migrations/20261115-hospital-campus-labels.sql`，分别补齐辅助表及历史通知、同步默认院区名称；后端启动也提供对应幂等初始化。已有订单和报告继续使用原快照，院区改名仅限定修正已知旧默认名称，不覆盖管理员自定义名称或其他业务字段。

## 本地入口

- 用户端：`http://127.0.0.1:8081/`
- 医生／管理端：`http://127.0.0.1:8089/`
- 既有用户 `13800000001` / `Health123!`；医生 `D001` / `Doctor123!`；管理员 `admin` / `Admin123!`。

大字模式会放大内容文字，较长表单及内容页允许自然滚动；默认字号下个人中心仍保持一屏菜单。体检、报告和医生资料均为课程实践内容，支付沿用本地模拟流程。

## 本地验证

两家默认体检机构现统一为“云医院-和平院区”“云医院-建设院区”；后端基础资料、历史订单名称快照、报告所引用的订单、通知中的机构名称和初始化已同步。医生与管理员共用页头、登录页移除“Neusoft 东软”，保留“体检报告管理系统”。

两端构建、后端打包和12项后端测试均通过；新增功能8项HTTP检查、4项并发检查及共10条浏览器用例通过。重启后报告、趋势、指南与消息已读状态保留。详细记录见 [验收结果](VALIDATION.md)。

首次初始化的用户账号包含课程报告。要体验同一体检人的两次报告趋势，启动系统后在仓库根目录执行 `npm run test:experience`，读取生成的 `output/test-results/experience-fixture.json` 中的账号与密码，再从首页进入“历次指标趋势”。脚本创建独立虚构资料，成功后停用它建立的机构与套餐，保留历史报告和通知供复查，不覆盖既有账号；生成的账号和输出不随源码上传。
